# Reviews and anchored discussion

Opening a review requires edit access to the document and review access for the proposed assignee.
The author of the selected revision cannot be its reviewer. Multiple revisions of one document can
be reviewed independently, but a duplicate open review for the same revision is rejected. The
review's original revision remains stable when the working copy advances.

Only the assigned reviewer can approve or reject. An administrator who needs another person to
decide must reassign the open review. Assignment validates the replacement's access and independence.
Closed reviews cannot be reassigned or decided again. A rejection can carry an explanation and
does not create a publication approval.

Discussion comments select a document revision and physical line number. Review-linked comments
must belong to the reviewed revision and an open review. Readers with access may comment;
editors resolve or reopen comments. Approval requires all comments associated with that review to
be resolved. An unrelated ordinary document comment is not automatically a publication blocker.

Comments continue to refer to their original revision after edits. A document's current body is
therefore insufficient to interpret an old comment. History and explicitly selected revision reads
provide the needed context. Retention preserves referenced comment and review revisions.

The application records review openings, reassignment, decisions, and discussion changes in its
audit journal. A failed operation creates no partial approval or audit entry. Review queries expose
status and unresolved counts to readers but do not bypass collection access checks.
